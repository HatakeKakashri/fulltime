# server-api-delivery — Tasks (Option A: API-first)

Implementation checklist for the Fastify + tRPC read-only API. Tasks are
ordered by dependency; each task bakes its own verification into the
checkbox line. Final integration is verified in Phase 5.

## 1. Scaffolding

- [ ] 1.1 Add Fastify + tRPC + zod + coris dependencies to `server/package.json` (run `bun install` from `server/` and verify the new entries appear in `bun.lock` with no install errors) — covers `fastify`, `@fastify/cors`, `@trpc/server`, `@trpc/client`, `zod`, plus `fastify-plugin` if needed by the adapter
- [ ] 1.2 Add `zod` and `@trpc/client` to `shared/package.json`, create `shared/src/contracts/index.ts` stub, and run `npx tsc --noEmit --project shared/tsconfig.json` to verify the workspace type-checks clean
- [ ] 1.3 Replace the `Bun.serve({ fetch: () => "Bun!" })` body in `server/src/index.ts` with a Fastify bootstrap (`const app = fastify({ logger: true }); await app.listen({ port: 3001 })`), keep `console.log` for the listen URL, and verify by running `bun run server/src/index.ts` and `curl http://localhost:3001/` returns the placeholder text without crashing
- [ ] 1.4 Register `@fastify/cors` with `origin: "http://localhost:5173"`, `methods: ["GET", "POST", "OPTIONS"]`, `allowedHeaders: ["Content-Type", "Authorization"]`, and verify by `curl -i -X OPTIONS http://localhost:3001/ -H 'Origin: http://localhost:5173' -H 'Access-Control-Request-Method: GET'` returns 204 with `access-control-allow-origin: http://localhost:5173`

## 2. Standings derivation

- [ ] 2.1 Create `server/src/derivation/standings.ts` exporting the `StandingsRow` zod schema (`position`, `clubId`, `clubName`, `played`, `won`, `drawn`, `lost`, `goalsFor`, `goalsAgainst`, `goalDifference`, `points`) and verify the file compiles via `npx tsc --noEmit --project server/tsconfig.json`
- [ ] 2.2 Implement the pure `deriveStandings(matches, clubs)` function (one pass over completed matches, 3/1/0 points, GD and GS accumulation, `position` 1-indexed after sort) in `server/src/derivation/standings.ts` and verify by writing `server/src/derivation/standings.test.ts` and running `bun test server/src/derivation/standings.test.ts` — the test for "full season" must assert exactly 20 rows with positions 1-20 and correct totals from a hand-built fixture set
- [ ] 2.3 Extract a named `compareStandingsRows(a, b)` comparator (points → GD → GS → alphabetical by clubId) and verify by adding one `describe("compareStandingsRows")` block in `server/src/derivation/standings.test.ts` with three tests — points-only tie, points+GD tie, points+GD+GS total tie — each asserting the documented ordering; `bun test server/src/derivation/standings.test.ts` passes all three

## 3. Router procedures

- [ ] 3.1 Create `server/src/trpc/context.ts` (Prisma client injection) and `server/src/trpc/router.ts` exporting `appRouter` with empty `leagueRouter` + `clubRouter` namespaces, wire the `@trpc/server/adapters/fastify` plugin in `server/src/index.ts`, and verify by `npx tsc --noEmit --project server/tsconfig.json` succeeds and `shared/src/contracts/index.ts` re-exports the `AppRouter` type
- [ ] 3.2 Implement `league.standings` (`query`, input `{ seasonId: uuid }`, output `{ rows: StandingsRow[] }`) in `server/src/trpc/procedures/league-standings.ts`, throwing `TRPCError(NOT_FOUND)` on unknown season, and verify by `server/src/trpc/procedures/league-standings.test.ts` integration test against a live PG fixture (mirror `season-scheduling.integration.test.ts` lifecycle) — the test asserts 20 rows for a fully simulated season and zero counters for clubs with no completed matches
- [ ] 3.3 Implement `league.fixtures` (`query`, input `{ seasonId: uuid, matchdayIndex?: int 1-38 }`, output `{ fixtures: FixtureView[] }`) in `server/src/trpc/procedures/league-fixtures.ts`, returning `NOT_FOUND` for unknown season or out-of-range matchday, and verify by `server/src/trpc/procedures/league-fixtures.test.ts` integration test — the test asserts 380 fixtures across 38 matchdays when no `matchdayIndex` is passed and exactly the matchday-1 fixtures when `matchdayIndex: 1` is passed
- [ ] 3.4 Implement `match.result` (`query`, input `{ matchId: uuid }`, output `{ match: MatchView }`) in `server/src/trpc/procedures/match-result.ts`, filtering `status = 'COMPLETED'` via the new `MATCH_STATUS.COMPLETED` constant and throwing `TRPCError(NOT_FOUND)` for missing rows or non-completed rows, and verify by `server/src/trpc/procedures/match-result.test.ts` integration test — the test injects one `status: 'COMPLETED'` row plus one `status: 'completed'` (lowercase) row and asserts only the uppercase row is returned, locking the casing reconciliation in place
- [ ] 3.5 Implement `club.squad` (`query`, input `{ clubId: uuid }`, output `{ club, players[20], startingXI: { playerIds[11], formation } }`) in `server/src/trpc/procedures/club-squad.ts`, resolving `StartingXI.playerIds` to full `PlayerView` records in starting order and exposing the `MVP_FORMATION` constant, and verify by `server/src/trpc/procedures/club-squad.test.ts` integration test — the test asserts exactly 20 players, exactly 11 starting XI ids, and `NOT_FOUND` for clubs without a computed XI
